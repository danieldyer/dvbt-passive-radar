PCIe uSDR capture
================
Build usdr-lib on dd/essential-rx-fixes and install into a chosen prefix. Enable
RADAR_BUILD_USDR=ON and add that prefix to CMAKE_PREFIX_PATH; RADAR_BUILD_UHD=OFF
is supported for a uSDR-only build. The configure check requires the native DMA
acquire/release API. Use the matching FPGA and kernel module from that branch.

In the existing recording JSON, add capture.driver="usdr". Defaults then become
bus=pcie, antenna=auto, and bandwidth_hz=28000000. Explicit example capture block:

  "capture": {
    "driver": "usdr", "device_args": "bus=pcie,dev=usdr0",
    "antenna": "EXT", "sample_rate_hz": 64000000,
    "centre_hz": 202000000, "gain_db": 30, "bandwidth_hz": 28000000,
    "buffer_seconds": 4, "clock_source": "internal", "time_source": "internal"
  }

Keep the recording/signals/transmitters declarations appropriate to the capture.
EXT (or rxl) selects the auxiliary HF/VHF converter. W (rxw) and H (rxh) select
the other RF paths; auto follows the driver's frequency table. Channel is zero.
Gain is nominal relative receiver gain, not measured gain at the antenna connector.
Applied rate, RF frequency, input, gain and bandwidth are read from the driver and
saved in diagnostics, summary and profile/channel archive metadata. Legacy JSON
continues to use UHD. Replay retains the declarations and labels its driver replay.

The converter rate can be 64 MS/s, but the RFIC low-pass filter's widest nominal
full RF bandwidth is 28 MHz. A requested bandwidth above 28 MHz selects bypass;
the recorded applied bandwidth is zero, meaning bypass, not a measured passband.
Capturing the five local channels across 56 MHz requires bench qualification of
bypass response, alias rejection, noise and blocker performance before relying on
those edge channels. The 28 MHz example deliberately uses the nominal filter
setting; it does not capture all five channels at full sensitivity.

Each DMA buffer is borrowed read-only and copied once, directly into the mapped
Vulkan CI16 receive ring. Partial ring spans retain the loan until fully copied;
stop releases it before DMA teardown. There is no intermediate sample buffer or
CPU conversion to float. GPU unpacking/channelization is unchanged. Direct DMA
into GPU memory is deferred. Actual sustained throughput must be measured on PL64.

Stream creation performs quiet-input analog DC calibration before reception.
There is no continuous RFIC servo and no FPGA digital DC subtraction. Hardware
sample timestamps locate quantified packet loss; unquantified ADC overflow stops
capture instead of fabricating coherent coordinates. No UTC anchor is invented.
Use the existing --simulate options for transport replay and the usual dvbt_capture
arguments for live capture. Run ctest -R 'usdr_capture|capture_replay|recording_input|live_archive'
after building their test targets. Live RF, loss/restart and performance tests await
the target; no hardware validation is implied by the mocked transport tests.
